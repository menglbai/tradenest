### 阶段 4：定位真正的 layout bug
用户在浏览器 console 跑：
```js
document.querySelector('#right-panel').getBoundingClientRect()
// → { x: 4844, y: 48, width: 350, height: 886 }
```

**真相**：right-panel 被推到屏幕外 4844 像素位置！  
原因：`grid-template-columns: 180px 1fr 350px` 中，`1fr` 让 chat-area 撑到 4844px（市场行情条 / 内联消息 / 某子元素无限撑开），把右栏挤出视口。

**修法**：
- chat-area: `flex: 1 1 0; width: 0; overflow: hidden`（强制 flex-basis=0）
- `.app` / `.main-area`: 加 `width: 100vw; max-width: 100vw; overflow: hidden`
- main-area 从 grid 改为 flexbox

### 阶段 5：发送消息后 AI 永远空气泡
后端日志清晰：`POST /chat/stream 200 → llm_stream_end → agent_stream_complete duration_ms=8114`，AI 实际回复完整。但前端 buffer 永远是 0。

加 `console.log` 后用户截图：`[stream] finally, buffer.length: 0` —— 一个 SSE 事件都没解析出来。

**用 `od -c` 抓后端真实字节**：
```
event: text_delta\r\ndata: {"text":"你好"}\r\n\r\n
```

**真相**：sse_starlette 用 CRLF（`\r\n\r\n`），前端用 `pending.indexOf('\n\n')` —— **永远找不到分隔符**！

**修法**：流入数据先 `.replace(/\r\n/g, '\n')` 规范化换行。

### 阶段 6：持仓数据全 0（字段名错位）

**真相**：前端字段名假设和后端实际返回完全不一致。

| 数据 | 后端实际 | 前端原代码 |
|---|---|---|
| 当前价 | `current_price` | 找 `price` |
| 涨跌幅% | `today_pct` | 找 `pct_change` |
| 持仓均价 | `avg_cost` | 找 `avg_price` |
| 持仓数量 | `total_shares` | 找 `quantity` |
| 总盈亏 | `total_profit` | 找 `total_pnl` |
| 今日盈亏 | `today_profit` | 找 `today_pnl` |

**修法**：前端兼容真实字段名（保留旧字段做 fallback）。

## 三、关键技术决策与教训

### 决策
- **前端单文件 HTML**：不引入 React/Vue 构建，CDN 加载 ECharts/marked/html2canvas
- **K 线数据源降级**：同花顺 → sina → mock（含失败容错）
- **AI System Prompt 自动注入**：每次对话自动携带持仓 / 关注实时数据，不依赖前端传递
- **Settings DB 持久化**：用户填的网关地址 / Cookie / API Key 全部存 SQLite，热更新
- **SSE 流式对话**：sse_starlette + 前端 fetch + ReadableStream
- **会话持久化**：SQLite，每条消息都写库，跨进程不丢

### 教训
1. **看到 UI 渲染问题，第一反应是 `getBoundingClientRect()` 测真实坐标，不是改 z-index**  
   今天浪费 1 小时打补丁，最后用 5 分钟拿坐标定位到 X=4844 才发现是 chat-area 撑爆推出视口。
2. **看到流式接收异常，第一反应是 `od -c` 抓真实字节**  
   不要猜 selector / DOM / lastBubble，先看真实数据流。CRLF vs LF 是经典坑。
3. **3 个以上 UI bug 同时出现，立刻整体重写**  
   不要再 edit 局部。每改一处都可能引发新 z-index 冲突。今天血泪教训。
4. **前后端字段名要严格对齐 contract**  
   今天后端返回 `current_price / total_shares / total_profit`，前端假设 `price / quantity / total_pnl`，全 fallback 到 0。应该有一份接口文档双方都看。

## 1. 项目概览

**TradeNest** 是一个长期陪伴自主研究型投资者的 AI 投资研究伙伴产品。

- **不是**投资顾问产品
- **不给**具体买卖建议
- **核心价值**：5 层持久记忆 + 多 Agent 分析 + 苏格拉底反问
- **技术栈**：Python 3.12 + FastAPI + Anthropic SDK + LangGraph + PG + Tauri + React

## 3. 核心约束

### 3.1 永远不写违规代码

❌ **绝对禁止**写代码生成以下内容：
- "建议买入 X / 卖出 X"
- 目标价 / 目标位
- 股价预测（"会涨到 X"）
- 收益承诺
- 推荐股票

✅ **只能写代码生成**：
- 客观信息整理
- 多视角辩论
- 反问引导
- 风险提示

#### 检查规则

如果用户让你写一个"推荐股票"功能，**拒绝**并说明合规边界。

### 3.2 5 层记忆是核心

每次代码涉及 AI 输出前：

```python
# 错误：忽略用户记忆
async def analyze_stock(code: str) -> str:
    data = await get_data(code)
    return await llm.generate(prompt=data)  # ❌ 通用分析

# 正确：加载 5 层记忆
async def analyze_stock(code: str, user_id: str) -> str:
    profile = await load_profile(user_id)        # L1
    framework = await load_framework(user_id)     # L2
    related_notes = await search_notes(code, user_id)  # L3
    related_decisions = await search_decisions(code, user_id)  # L4
    recent_convs = await load_recent_convs(user_id)    # L5
    
    return await llm.generate(
        system_prompt=build_with_memory(profile, framework),
        context=[*related_notes, *related_decisions, *recent_convs],
        user_message=f"分析 {code}",
    )
```

### 3.3 苏格拉底优先

在 AI 对话相关的代码中：
- 不出"AI 推荐"
- 出"AI 反问"
- 触发条件参考 [AGENT-DESIGN.md §9](./AGENT-DESIGN.md#9-苏格拉底对话策略)

### 3.4 用户框架优先

用户的 L2 研究框架是 AI 输出的**约束条件**：

```python
# 错误
def analyst_prompt(stock: Stock) -> str:
    return f"分析 {stock.name}，给出投资建议。"  # ❌

# 正确
def analyst_prompt(stock: Stock, framework: ResearchFramework) -> str:
    return f"""
    按用户的研究框架分析 {stock.name}。
    
    用户框架要求检查：
    {format_checklist(framework.checklist)}
    
    Deal-breakers（不能跳过）：
    {format_deal_breakers(framework.deal_breakers)}
    
    输出**事实**和**多视角观点**，不输出建议。
    """
```

## 4. 代码风格约定

### 4.1 Python

```python
# 用 type hint
def add(a: int, b: int) -> int:
    return a + b

# 用 async / await
async def fetch_data(code: str) -> dict[str, Any]:
    ...

# 用 dataclass / Pydantic
from pydantic import BaseModel

class StockQuote(BaseModel):
    code: str
    price: float
    change_pct: float

# 用 structlog
import structlog
log = structlog.get_logger()
log.info("agent_started", user=user_id, query=query)
```

### 4.2 TypeScript

```typescript
// 严格 TS
function add(a: number, b: number): number {
  return a + b;
}

// 用 Zustand 而不是 Context
import { create } from 'zustand';

// 用 shadcn/ui 组件
import { Button } from '@/components/ui/button';
```

### 4.3 通用

- 函数 < 50 行
- 文件 < 500 行
- 不写大段注释（代码自解释）
- 关键决策**写到 DECISIONS.md** 不写在代码注释

## 5. Commit 风格（Conventional Commits）

```
feat: 新功能
fix: 修 bug
docs: 仅文档
style: 不影响代码运行
refactor: 重构
perf: 性能优化
test: 测试相关
chore: 构建 / 工具
ci: CI/CD

例：
feat(agent): 实现 BullResearcher Agent
fix(memory): 修 L3 笔记向量索引性能
docs(prd): 更新模块 D 苏格拉底对话章节
```

每次 commit 前：
- 跑过 `ruff check`
- 跑过 `mypy`（关键文件）
- 跑过 `pytest`（相关测试）

## 6. 测试要求

### 6.1 必须有测试的代码

- 所有 `tools/` 下的工具
- 所有 `agents/` 下的 Agent
- 所有 `compliance/` 合规审查

### 6.2 不必有测试的

- 单纯的数据模型 schema
- UI 组件
- 一次性脚本

### 6.3 合规测试必须

```python
# 任何 AI 输出代码必须有合规测试
@pytest.mark.parametrize("input_text", LOAD_FORBIDDEN_QUERIES())
async def test_no_violation(input_text: str):
    output = await run_agent(input_text)
    assert no_compliance_violation(output)
```

## 7. 常见任务工作流

### 7.1 新增工具

```
1. 在 packages/server/tradenest/tools/ 下找到合适的子目录
2. 创建新文件 my_new_tool.py
3. 实现工具：
   from tradenest.tools.base import register_tool
   
   @register_tool(name="my_new_tool", description="...", input_schema={...})
   async def my_new_tool(...) -> ToolResult:
       ...
4. 在 tests/test_tools/ 写测试
5. 在 AGENT-DESIGN.md §3.1 工具清单更新
6. commit: feat(tools): 添加 my_new_tool
```

### 7.2 新增 Agent

```
1. 读 AGENT-DESIGN.md §2 多 Agent 编排
2. 在 packages/server/tradenest/agents/ 下创建 my_agent.py
3. 写 system prompt（参考 §2.2 模板）
4. 实现 Agent function
5. 写测试（含合规测试）
6. 在 AGENT-DESIGN.md 注册
7. commit: feat(agent): 添加 MyAgent
```

### 7.3 新增数据源

```
1. 在 packages/server/tradenest/data/sources/ 下创建 provider
2. 实现 BaseProvider 接口
3. 在 data/normalizer.py 加归一化
4. 写工具（参考 §7.1）
5. commit: feat(data): 接入 X 数据源
```

### 7.4 数据库迁移

```
1. 修改 packages/server/tradenest/storage/models.py
2. uv run alembic revision --autogenerate -m "add xxx"
3. 检查生成的迁移文件
4. uv run alembic upgrade head（本地测试）
5. 在 DATA-MODEL.md 更新表说明
6. commit: feat(db): 添加 xxx 表
```

### 7.5 修改 PRD

如果你（AI Agent）发现 PRD 不准确或缺漏：

```
1. 在 DECISIONS.md 创建新 ADR（解释为什么改）
2. 修改 PRD.md
3. 更新相关其他文档
4. commit: docs(prd): 修订 §X 章节
```

**绝不**直接改 PRD 而不写 ADR。

## 8. 调试技巧

### 8.1 Agent 调试

每次 Agent 运行都会写到 `agent_run` 表（含完整 trace）。

```bash
# 看最近的 Agent 运行
psql -c "SELECT id, started_at, status, total_tokens_input + total_tokens_output AS tokens FROM agent_run ORDER BY started_at DESC LIMIT 10;"

# 看具体某次的 trace
psql -c "SELECT trace FROM agent_run WHERE id = 'xxx';"
```

### 8.2 工具调用调试

```bash
psql -c "SELECT tool_name, input, output, duration_ms FROM tool_call WHERE agent_run_id = 'xxx';"
```

### 8.3 日志

```python
import structlog
log = structlog.get_logger("tradenest.agents.market_analyst")
log.info("analyst_invoked", stock_code=code, user_id=user_id)
```

启动时设置 log level：

```bash
TRADENEST_LOG_LEVEL=DEBUG uv run uvicorn tradenest.main:app --reload
```

## 10. 给 AI Agent 的特别提醒

### 10.1 不要 fetch / clone 参考项目代码

**绝不**让 AI 助手去 `git clone https://github.com/hsliuping/TradingAgents-CN`。

我们要的是**借鉴业务设计 + 完全自己写代码**。详见 [REFERENCES.md](./0004-参考项目分析.md) §7。

### 10.2 不要"自作聪明"做投顾功能

如果用户的需求有"推荐股票"或"预测股价"嫌疑——**先拒绝**并解释合规边界。

如果用户坚持——**仍然拒绝**。这是项目生死线。

### 10.3 优先 dogfood

任何新功能想"我自己用不用"。如果作者本人不用，**砍掉**。

### 10.4 文档驱动

- 新功能：先在 PRD / AGENT-DESIGN 写设计，再写代码
- 新决策：先在 DECISIONS.md 写 ADR，再实施
- 新数据：先在 DATA-MODEL.md 写表，再迁移

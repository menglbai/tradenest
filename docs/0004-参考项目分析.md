## 1. 主要参考：TradingAgents-CN

### 1.1 项目概况

| 项 | 值 |
|---|---|
| **仓库** | https://github.com/hsliuping/TradingAgents-CN |

### 1.2 核心架构（重要！）

#### 多 Agent 编排

TradingAgents-CN 的核心是 4 层 Agent 编排：

```
┌────────────────────────────────────────┐
│  第一层：分析师团队（5 个）              │
├────────────────────────────────────────┤
│ - market_analyst         技术面          │
│ - fundamentals_analyst   基本面          │
│ - news_analyst           新闻             │
│ - social_media_analyst   情绪             │
│ - china_market_analyst   A 股特色        │
└──────────┬─────────────────────────────┘
           ↓
┌────────────────────────────────────────┐
│  第二层：研究员（多空辩论）              │
├────────────────────────────────────────┤
│ - bull_researcher        看多派          │
│ - bear_researcher        看空派          │
└──────────┬─────────────────────────────┘
           ↓
┌────────────────────────────────────────┐
│  第三层：风控（三方辩论）                │
├────────────────────────────────────────┤
│ - aggressive_debator     激进派          │
│ - conservative_debator   保守派          │
│ - neutral_debator        中立派          │
└──────────┬─────────────────────────────┘
           ↓
┌────────────────────────────────────────┐
│  第四层：综合输出                        │
├────────────────────────────────────────┤
│ - research_manager       研究主管        │
│ - risk_manager           风控主管        │
│ - trader                 综合输出        │
└────────────────────────────────────────┘
```

#### 仓库结构（核心）


### 1.3 数据源

- **A 股**：AkShare、Tushare、BaoStock
- **港股**：providers/hk
- **美股**：providers/us
- **新闻**：realtime_news_utils

### 1.4 LLM 适配

支持：
- DashScope（阿里通义）
- DeepSeek
- Google AI（Gemini）
- OpenAI 兼容协议（含国产模型）
- AiHubMix（聚合 LLM）

### 1.5 合规策略（关键学习点）

**README 原文**：

> 面向中文用户的**多智能体与大模型股票分析学习平台**。帮助你系统化学习如何使用多智能体交易框架与 AI 大模型进行**合规的股票研究与策略实验**，**不提供实盘交易指令**，平台定位为**学习与研究用途**。

#### 合规设计要点

1. **明确"学习与研究"定位**——不是投顾产品
2. **不提供实盘交易指令**——避开自动交易合规
3. **多 Agent 辩论代替单一建议**——天然规避"具体推荐"
4. **输出多空双方观点**——不下结论
5. **风控视角强制存在**——必有"反对意见"

这套合规策略**值得我们 100% 借鉴**。

### 1.6 商业 / 法律状态

#### 版权声明

TradingAgents-CN 在 README 顶部明确：
- ❌ 项目组**没有给任何组织或个人进行过商业授权**
- ❌ 网站 `tradingagents-ai.com` 未经授权使用代码（侵权警告）
- ⚠️ v2.0 因盗版问题**不开源**

#### 许可证细分

| 路径 | License | 商用 |
|------|---------|------|
| 除 `app/` 和 `frontend/` 外 | Apache 2.0 | ✅ |
| `app/`（FastAPI 后端）| 专有 | ❌ 需授权 |
| `frontend/`（Vue 前端）| 专有 | ❌ 需授权 |

**核心 `tradingagents/` 包是 Apache 2.0**，理论上可以集成使用——但我们选择**不集成**（详见后面 §3）。

## 2. 我们借鉴什么

### 2.1 借鉴：多 Agent 业务架构 ⭐⭐⭐⭐⭐

#### 借鉴的内容

- 5 分析师角色定义
- 多空辩论模式
- 三方风控辩论
- 综合输出 Agent

#### 借鉴的具体方式

**直接 1:1 借鉴角色清单**：

```
TradeNest 多 Agent          来源
─────────────────          ──────────
MarketAnalyst              ← market_analyst
FundamentalsAnalyst        ← fundamentals_analyst
NewsAnalyst                ← news_analyst
SocialSentimentAnalyst     ← social_media_analyst
ChinaSpecificAnalyst       ← china_market_analyst
BullResearcher             ← bull_researcher
BearResearcher             ← bear_researcher
AggressiveRiskRater        ← aggressive_debator
ConservativeRiskRater      ← conservative_debator
NeutralRiskRater           ← neutral_debator
Synthesizer                ← research_manager + trader 综合
```

#### 改造的部分

虽然角色名借鉴，但**实现完全自己写**：
- 用 Anthropic SDK 而不是他们的 LangChain
- 用 LangGraph 编排而不是他们的自定义图
- 加入用户的 L2 框架约束（他们没有）
- 输出喂给我们的 5 层记忆（他们没有）

### 2.2 借鉴：合规策略 ⭐⭐⭐⭐⭐

#### 借鉴的内容

- "学习与研究"定位话术
- 多 Agent 辩论代替单一建议
- 强制风控视角
- 不提供实盘交易指令

#### 改造的部分

我们更严格：
- 加了**关键词后置审查**（他们似乎没有）
- 加了**用户协议**首次确认
- 加了**输出免责声明**模板

详见 [COMPLIANCE.md](./0002-合规边界.md)。

### 2.3 借鉴：A 股数据源选型 ⭐⭐⭐⭐

#### 借鉴的内容

- AkShare 作为主用
- Tushare 作为备选
- BaoStock 作为补充

#### 改造的部分

- 加入 Playwright 抓取（公众号 / 雪球 / 知乎）——他们没有
- 不用 MongoDB 缓存，用 Redis + PG

### 2.4 借鉴：LLM 多 Provider 抽象设计 ⭐⭐⭐

#### 借鉴的内容

- LLM 适配层概念
- 多 Provider 切换能力
- OpenAI 兼容协议作为通用接口

#### 改造的部分

- 用 LiteLLM 或自己写轻量路由
- 加入按任务复杂度自动选模型的逻辑（他们似乎没有）

### 2.5 借鉴：报告生成 ⭐⭐⭐

#### 借鉴的内容

- 结构化分析报告概念
- Markdown 输出
- 多视角组合

#### 改造的部分

- 报告自动存入 L3 研究笔记
- 报告关联 L4 决策档案
- 报告引用用户历史研究

### 2.6 借鉴：业务流程图 ⭐⭐⭐⭐

#### 借鉴的内容

整体流程：
```
用户提股票 → 拉数据 → 5 分析师并行 → 多空辩论 → 风控辩论 → 综合输出
```

这套流程**经过 26554 stars 用户验证**，是合理的 baseline。

#### 改造的部分

- 加入"加载 5 层记忆"前置步骤
- 加入"按用户 L2 框架约束"中间步骤
- 加入"苏格拉底反问"后置步骤
- 加入"存入用户记忆"后处理步骤

## 3. 我们不借鉴什么 + 为什么

### 3.1 不借鉴：代码 ⛔

#### 原因

| 原因 | 说明 |
|------|------|
| **学习目的** | 项目目标是"用上 cc 全部核心技术"——抄代码达不到这个目的 |
| **License 限制** | `app/` 和 `frontend/` 是专有，商用要授权 |
| **架构差异** | 我们用 Anthropic SDK + LangGraph，跟他们的实现不同 |
| **可控性** | 自己写代码可以深度集成 5 层记忆 |
| **社区印象** | 避免被认为是 fork，影响项目独立性 |

#### 我们的策略

- **不 import** `tradingagents` 包
- **不 fork** 仓库
- **业务流程参考**：可以读他们 README / 文档，但不读核心代码
- **角色名可借鉴**：分析师 / 研究员 / 风控这套词汇是行业通用，不算抄

### 3.2 不借鉴：Web 形态 ⛔

#### 原因

TradingAgents-CN 是 **FastAPI + Vue Web 应用**——这跟我们定位完全不同：

| 维度 | TradingAgents-CN | TradeNest |
|------|------------------|-----------|
| 形态 | Web 应用 | 桌面客户端 + 浏览器扩展 |
| 用户体验 | 浏览器打开网址 | 装在本地，随时打开 |
| 数据 | 集中存储 | 用户本地 |
| 隐私 | 看云端架构 | 本地优先 |

我们做**长期陪伴的桌面产品**，Web 形态不适合。

### 3.3 不借鉴：单次分析模式 ⛔

#### 原因

TradingAgents-CN 是**单次分析工具**：
- 输入股票代码
- 输出一份分析报告
- 不记得上次分析的内容
- 没有跨时间维度

我们做**长期陪伴产品**：
- 记得用户所有研究
- 跨时间反馈
- 基于历史决策反问

完全不同的物种。

### 3.4 不借鉴：MongoDB 数据库 ⛔

#### 原因

| 维度 | TradingAgents-CN（MongoDB）| TradeNest（PostgreSQL）|
|------|--------------------------|----------------------|
| 数据类型 | 文档型 | 关系型 |
| 向量搜索 | 需插件 | pgvector 原生 |
| 一致性 | 弱 | 强 |
| 关联查询 | 弱 | 强 |
| 运维 | 中 | 简单 |

我们的 5 层记忆有**复杂的关联关系**（笔记关联决策、决策关联对话等），关系型数据库更合适。

### 3.5 不借鉴：Vue 前端 ⛔

我们用 React 19 + TypeScript（详见 ADR-003）。

### 3.6 不借鉴：业务输出"建议"风格 ⛔

#### 原因

观察 TradingAgents-CN 的输出，部分场景仍接近"给建议"：
- "trader" Agent 的最终输出像综合建议
- 风控评级有时像投资评级

我们的策略**更严格**：
- 完全不出"trader 建议"——只出"多空辩论 + 反问"
- 不给"评级"——只给"按用户框架的事实打分"
- 强制苏格拉底反问

详见 [COMPLIANCE.md](./0002-合规边界.md) 和 ADR-014。

## 4. 差异化对比表

### 4.1 核心维度对比

| 维度 | TradingAgents-CN | TradeNest |
|------|------------------|-----------|
| **形态** | Web 应用 | 桌面客户端 + 浏览器扩展 |
| **使用模式** | 单次分析 | 长期陪伴 |
| **持久记忆** | 无 | 5 层持久记忆 |
| **个人化** | 通用分析 | 用户画像 + L2 框架约束 |
| **用户研究框架** | 不支持 | 必填 + 强制约束 AI |
| **跨时间反馈** | 无 | ✅ 反问 |
| **苏格拉底对话** | 无 | ✅ 核心 |
| **主动推送** | 无 | ✅ 桌面通知 |
| **复盘系统** | 无 | ✅ 周/月/年报 |
| **决策档案** | 无 | ✅ L4 |
| **信息流抓取** | 仅基础数据 | + 公众号/雪球/知乎（Playwright）|
| **Skills 系统** | 无 | ✅（OpenClaw 思路）|
| **Hook 系统** | 无 | ✅（Claude Code 思路）|
| **数据库** | MongoDB | PostgreSQL + pgvector |
| **前端** | Vue 3 + Element Plus | React 19 + shadcn/ui |
| **桌面/扩展** | 无 | Tauri + WXT |
| **Agent 框架** | 自写 + LangChain | Anthropic SDK + LangGraph |
| **License** | 混合（核心 Apache + 应用专有）| Apache 2.0（统一）|
| **目标用户** | 学习者 | 自主研究型投资者 |

### 4.2 共同点

- 都是中文 AI 投资工具
- 都用多 Agent 架构
- 都严守合规（不投顾）
- 都用 AkShare 等开源数据源
- 都支持多 LLM Provider
- 都是开源项目

### 4.3 谁强在哪

#### TradingAgents-CN 强在

- **大社区**：26554 stars，活跃讨论
- **学术血统**：基于 Tauric Research，有论文支撑
- **多 LLM 适配成熟**：DashScope / DeepSeek / Google 都支持
- **覆盖完整**：A股 + 港股 + 美股
- **报告导出多格式**：MD / Word / PDF

#### TradeNest 强在

- **持久记忆**：5 层结构化记忆
- **真正个人化**：用户的 L2 框架约束 AI
- **苏格拉底对话**：决策时反问
- **桌面体验**：长期陪伴
- **主动推送**：盯着市场
- **复盘系统**：跨时间成长可视化
- **更严的合规**：三道审查防线

### 4.4 谁是谁的替代品？

**都不是**。它们是**不同物种**：

- TradingAgents-CN：**学习者 / 研究者**的"多 Agent 学习平台"
- TradeNest：**自主投资者**的"长期 AI 研究伙伴"

可以共存，甚至互补使用。

## 6. 参考的合规与法律边界

### 6.1 不抄代码原则

- ❌ 不复制粘贴他人代码到 TradeNest
- ❌ 不直接 import 专有部分
- ✅ 可以阅读公开 README / 文档
- ✅ 可以借鉴架构思路、业务流程
- ✅ 可以使用相同的开源工具（AkShare 等）

### 6.2 合理引用

代码 / 文档中提到 TradingAgents-CN 时：

```python
# 注释示例
# 多 Agent 业务流程参考自 TradingAgents-CN 项目
# https://github.com/hsliuping/TradingAgents-CN
# 但实现完全独立，未引用其代码
```

或在 README 中：

```markdown
## 致谢

TradeNest 的多 Agent 业务设计借鉴自 [TradingAgents-CN](https://github.com/hsliuping/TradingAgents-CN)（Apache 2.0）。
我们仅借鉴业务流程，代码完全独立编写。
```

### 6.3 商标与品牌

- ❌ 不使用"TradingAgents"作为我们的功能/模块名
- ❌ 不暗示 TradeNest 是 TradingAgents 的延续
- ✅ 公开承认借鉴

### 6.4 数据源合规

借鉴 TradingAgents-CN 的数据源选择（AkShare / Tushare）— 这些都是**开源数据源**，无版权问题。

## 7. 结论

### 7.1 一句话总结

> **TradeNest 借鉴 TradingAgents-CN 的"多 Agent 业务设计"作为分析能力的 baseline，
> 但我们的核心差异化（5 层记忆 / 苏格拉底对话 / 长期陪伴 / 桌面形态）是 TradingAgents-CN 没做的，
> 这两个项目是不同物种，可共存。**

### 7.2 给开发者的建议

- 阅读 TradingAgents-CN 的 README、PRD-类文档（如有）
- **不要读它的代码细节**（避免"抄"嫌疑 + 影响独立思考）
- 业务流程理解后，**用我们的技术栈重新实现**
- 实现时记得把"5 层记忆 / 苏格拉底"集成进去

### 7.3 给 AI Agent / Coding 助手的指令

如果 AI 助手在写 TradeNest 代码时被诱惑去 fetch / clone TradingAgents-CN 代码——

**不要做**。我们要的是"借鉴业务设计 + 完全自己写代码"。

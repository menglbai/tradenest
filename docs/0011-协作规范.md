## 1. 开发环境搭建

### 1.1 必装工具

```bash
# uv（Python 包管理）
curl -LsSf https://astral.sh/uv/install.sh | sh

# pnpm（前端包管理）
npm i -g pnpm

# Docker（PG + Redis）
# 见 https://docs.docker.com/install/
```

### 1.2 一键安装

```bash
git clone https://github.com/<your>/tradenest.git
cd tradenest
./scripts/setup.sh
```

### 1.3 起开发环境

```bash
# 起 PG + Redis
docker compose -f docker/docker-compose.dev.yml up -d

# 配 .env
cp .env.example .env
# 填入 ANTHROPIC_API_KEY 等

# 后端
cd packages/server
uv sync
uv run alembic upgrade head
uv run uvicorn tradenest.main:app --reload

# 桌面（另开终端）
cd apps/desktop
pnpm install
pnpm tauri dev
```

## 2. 代码风格

### 2.1 Python

#### 工具

- **Ruff**：lint + format（替代 Black / isort / flake8）
- **mypy strict**：类型检查

#### 配置

```toml
# pyproject.toml
[tool.ruff]
line-length = 100
target-version = "py312"

[tool.ruff.lint]
select = ["E", "W", "F", "I", "B", "C4", "UP", "N", "ASYNC", "S", "RUF"]
ignore = ["E501"]

[tool.mypy]
python_version = "3.12"
strict = true
```

#### 规范

```python
# 1. 用 type hint
def greet(name: str) -> str:
    return f"Hello, {name}"

# 2. async first
async def fetch_data(code: str) -> dict[str, Any]:
    ...

# 3. 用 Pydantic 而不是 dict
class Quote(BaseModel):
    code: str
    price: float

# 4. 用 structlog
import structlog
log = structlog.get_logger()

# 5. 用 pathlib
from pathlib import Path
config_dir = Path.home() / ".tradenest"

# 6. 不用裸 except
try:
    ...
except SpecificException as e:
    log.error("...", error=str(e))
    raise
```

### 2.2 TypeScript

#### 工具

- **Biome**：lint + format（替代 ESLint + Prettier）
- **tsc**：类型检查

#### 配置

```json
// biome.json
{
  "linter": {
    "enabled": true,
    "rules": {
      "recommended": true,
      "correctness": {
        "noUnusedVariables": "error"
      }
    }
  },
  "formatter": {
    "indentStyle": "space",
    "indentWidth": 2
  }
}
```

#### 规范

```typescript
// 1. 严格 TS（tsconfig "strict": true）
function greet(name: string): string {
  return `Hello, ${name}`;
}

// 2. Zustand 状态管理
import { create } from 'zustand';

// 3. shadcn/ui 优先
import { Button } from '@/components/ui/button';

// 4. fetch 用 ofetch（不用 axios）
import { $fetch } from 'ofetch';

// 5. 不用 any
const data = JSON.parse(text) as Quote;  // ✅
const data = JSON.parse(text) as any;     // ❌
```

### 2.3 Markdown

- 标题用 `#` 不用 `===`
- 代码块标语言（```python 而不是 ```）
- 表格用对齐
- 链接相对路径（`./file.md` 而不是绝对路径）

## 3. Commit 规范

### 3.1 Conventional Commits

```
<type>(<scope>): <subject>

[optional body]

[optional footer]
```

#### Type

| Type | 用途 |
|------|------|
| feat | 新功能 |
| fix | 修 bug |
| docs | 仅文档 |
| style | 不影响代码运行 |
| refactor | 重构 |
| perf | 性能优化 |
| test | 测试相关 |
| chore | 构建 / 工具 |
| ci | CI/CD |
| revert | 回滚 |

#### Scope（可选）

```
agent / memory / tools / data / api / desktop / extension / docs / etc.
```

#### 示例

```
feat(agent): 实现 BullResearcher Agent

支持多空辩论的看多研究员 Agent。
- 输入：5 分析师报告
- 输出：看多核心论据 + 反驳
- 含合规审查测试

Refs #42
```

### 3.2 不要这样 commit

```
❌ "更新代码"
❌ "fix bug"
❌ "WIP"
❌ "."
```

## 4. Branch 策略

### 4.1 主分支

- `main`：稳定主分支，受保护
- 不允许直接 push 到 main
- 通过 PR 合入

### 4.2 工作分支

```
feature/记忆系统-l3
fix/合规审查-边界条件
refactor/agent-编排
docs/prd-更新
chore/升级依赖
```

### 4.3 分支生命周期

```
1. 从 main checkout 新分支
2. 开发 + commit
3. push 到 origin
4. 提 PR
5. CI 通过 + Code Review 通过
6. Squash merge 到 main
7. 删除分支
```

## 5. PR 流程

### 5.1 PR 模板

```markdown
## 变更摘要

[一句话说明这个 PR 做了什么]

## 变更类型

- [ ] 新功能（feat）
- [ ] 修 bug（fix）
- [ ] 文档（docs）
- [ ] 重构（refactor）
- [ ] 性能（perf）
- [ ] 其他

## 关联 Issue

Closes #XXX

## 测试

- [ ] 单元测试已加
- [ ] 集成测试已跑
- [ ] 合规测试已通过（如涉及 AI 输出）

## 文档

- [ ] PRD 已更新（如需要）
- [ ] AGENT-DESIGN 已更新（如需要）
- [ ] CHANGELOG 已更新

## ADR

[ ] 涉及重大决策？已写 ADR？链接：

## 截图 / Demo

[如有 UI 变化]

## 检查表

- [ ] ruff check 通过
- [ ] mypy 通过
- [ ] pytest 通过
- [ ] commit 消息符合 Conventional Commits
```

### 5.2 PR 大小

- **小 PR**：< 200 行变更（最佳）
- **中 PR**：200-500 行
- **大 PR**：>500 行（需特别说明）

大 PR 应拆分为多个小 PR。

### 5.3 Code Review 标准

#### 必须达成

- ✅ CI 全绿
- ✅ 测试覆盖足够
- ✅ 代码无明显坏味道
- ✅ 不违反 [COMPLIANCE.md](./0002-合规边界.md)

#### Reviewer 必查

- 是否引入合规风险？
- 是否破坏现有功能？
- 是否有性能问题？
- 是否文档同步？

## 6. 测试要求

### 6.1 覆盖率目标

| 模块 | 目标 |
|------|------|
| `agents/` / `memory/` / `tools/` / `compliance/` | 80%+ |
| `api/` / `data/` | 70%+ |
| 整体 | 70%+ |

### 6.2 测试类型

#### 单元测试（pytest）

```python
# tests/unit/test_compliance.py
def test_check_compliance_forbidden_phrase():
    text = "建议买入贵州茅台"
    result = check_compliance(text)
    assert not result.passed
    assert any("建议(买入" in v for v in result.violations)
```

#### 集成测试

```python
# tests/integration/test_agent_flow.py
async def test_full_analysis_flow():
    result = await run_agent("分析贵州茅台 600519")
    assert result.status == "completed"
    assert len(result.analyst_reports) == 5
    assert result.compliance_check_passed
```

#### E2E（Playwright）

```typescript
// tests/e2e/chat.spec.ts
test('user can send message and see response', async ({ page }) => {
  await page.goto('/');
  await page.fill('[data-testid="chat-input"]', '茅台多少钱');
  await page.click('[data-testid="send-btn"]');
  await expect(page.locator('[data-testid="ai-response"]')).toBeVisible();
});
```

### 6.3 合规测试（必须）

任何涉及 AI 输出的代码：

```python
@pytest.mark.parametrize("query", [
    "我该买茅台吗",
    "茅台目标价",
    "推荐几只股",
])
async def test_no_recommendation(query: str):
    result = await run_agent(query)
    forbidden = ["建议买入", "建议卖出", "目标价 \\d", "推荐你买"]
    for f in forbidden:
        assert not re.search(f, result.output)
```

## 7. 文档要求

### 7.1 必须同步更新文档

| 改动 | 必更新 |
|------|--------|
| 新功能 | PRD.md / CHANGELOG.md |
| 新 Agent | AGENT-DESIGN.md |
| 新工具 | AGENT-DESIGN.md §3 |
| 新数据库表 | DATA-MODEL.md |
| 新技术栈 | TECH-STACK.md |
| 重大决策 | DECISIONS.md（新 ADR） |
| 合规规则 | COMPLIANCE.md |

### 7.2 文档原则

- **不写废话**：每段都有信息量
- **多用表格 / 列表**：可扫读
- **代码示例必可运行**
- **链接相对路径**

## 8. ADR 流程

### 8.1 何时写 ADR

任何**不可轻易回滚**的决策：

- 选某个框架 / 库
- 数据库 schema 重大变化
- API 协议变化
- 合规策略变化
- 模块重大重构

### 8.2 ADR 流程

```
1. 在 DECISIONS.md 末尾加新 ADR
2. 状态先标 Proposed
3. PR 描述链接到这个 ADR
4. Code Review 时讨论
5. 合并 PR 时 ADR 状态改为 Accepted
6. 实施
```

见 [DECISIONS.md](./0003-决策日志ADR.md) 顶部模板。

## 10. 安全披露

### 10.1 发现安全问题怎么办

**不要在 GitHub Issue 公开报告**。

请通过以下方式私下联系：
- Email：（待补充）
- 加密：可用 PGP

### 10.2 报告内容

- 问题描述
- 复现步骤
- 影响范围
- 建议修复

### 10.3 响应时效

- **24 小时内**：确认收到
- **7 天内**：评估 + 初步修复方案
- **30 天内**：发布修复（视严重度）

### 10.4 致谢

非恶意披露我们会在 CHANGELOG / SECURITY.md 致谢（征求同意）。

## 11. 行为准则

### 11.1 协作精神

- 假设善意（assume good intent）
- 对事不对人
- 接受批评，提供建设性反馈
- 不容忍歧视 / 骚扰

### 11.2 决策原则

- **数据 > 直觉**
- **合规 > 速度**
- **dogfood > 假设用户**
- **简单 > 聪明**

## 1. 系统要求

### 必须
- **Python 3.11+**（推荐 3.12，但 3.11 也能跑）
- **uv**（Python 包管理器，必装）
- **网络**：能访问 LLM 网关（默认是小红书内部 codewiz）

### 可选
- **AkShare 数据源**：能访问东方财富（公网）

### 不需要的
- ❌ PostgreSQL（Phase 0 不用）
- ❌ Redis（Phase 0 不用）
- ❌ Docker（Phase 0 不用）
- ❌ Node.js（后端不用，前端 Phase 1 末才做）

### 安装 uv（一行）

```bash
# Mac / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# 验证
uv --version
```

## 2. 一步步启动

### 步骤 1：拉代码

```bash
git clone https://github.com/menglbai/tradenest.git
cd tradenest
```

或者已经 clone 过：
```bash
cd 你的tradenest目录
git pull origin main
```

### 步骤 2：进入后端目录 + 创建虚拟环境

```bash
cd packages/server
uv venv
```

会在 `packages/server/.venv/` 创建虚拟环境（自带 pip，约 30 秒）。

### 步骤 3：安装依赖

#### 国内（小红书内网）

```bash
UV_INDEX_URL=https://artifactory.devops.xiaohongshu.com/artifactory/api/pypi/pypi-public/simple/ \
uv pip install --allow-insecure-host artifactory.devops.xiaohongshu.com \
  fastapi 'uvicorn[standard]' httpx anthropic akshare pandas \
  pydantic pydantic-settings python-dotenv structlog rich sse-starlette
```

#### 公网（境外或不走内网）

```bash
uv pip install \
  fastapi 'uvicorn[standard]' httpx anthropic akshare pandas \
  pydantic pydantic-settings python-dotenv structlog rich sse-starlette
```

### 步骤 4：配置环境变量

```bash
# 在仓库根目录
cd ../..   # 回到 tradenest/ 根
cp .env.example .env
```

打开 `.env`，按需填写。**默认配置（不改也能用）**：

```env
# 默认走小红书内部 codewiz 网关，不需要 API key
TRADENEST_DEFAULT_PROVIDER_ID=internal-xhs

# 内部网关地址 + 认证（已有合理默认值，无需改）
TRADENEST_XHS_INTERNAL_BASE_URL=http://codewiz.devops.xiaohongshu.com/llmadapter/anthropic
TRADENEST_XHS_INTERNAL_USER_EMAIL=baimenglong@xiaohongshu.com
```

> 如果不在小红书内网，需要改 `TRADENEST_DEFAULT_PROVIDER_ID` 为 `anthropic-public` 或 `deepseek` 等，并填对应的 API key。详见[第 6 节](#6-多-provider-切换)。

### 步骤 5：测试是否跑通

#### 方法 A：CLI 命令行（最快）

```bash
cd packages/server

# 看系统信息
uv run python -m tradenest.cli info

# 测 LLM Provider 是否可用
uv run python -m tradenest.cli health

# 问个问题
uv run python -m tradenest.cli ask "你好，介绍一下你自己"

# 让 AI 调工具（mock 数据）
uv run python -m tradenest.cli ask "用 mock 工具查下贵州茅台 600519"

# 真实行情（需要能访问东财）
uv run python -m tradenest.cli ask "贵州茅台现在多少钱？"

# 流式输出
uv run python -m tradenest.cli ask "分析下宁德时代" --stream
```

#### 方法 B：Web 服务 + curl

```bash
cd packages/server

# 启动 FastAPI 服务
uv run uvicorn tradenest.main:app --reload --host 0.0.0.0 --port 8000
```

另开一个终端：

```bash
# 健康检查
curl http://localhost:8000/health

# 系统信息
curl http://localhost:8000/system/info | jq

# Provider 列表
curl http://localhost:8000/system/providers | jq

# 工具列表
curl http://localhost:8000/system/tools | jq

# 对话（非流式）
curl -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"你好"}' | jq

# 对话（流式 SSE）
curl -X POST http://localhost:8000/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"message":"分析下贵州茅台"}'
```

#### 方法 C：浏览器 OpenAPI 文档

启动 Web 服务后，浏览器打开：
```
http://localhost:8000/docs
```

可以**直接在网页上点按钮调 API**——不用写 curl。

## 4. 常见问题

### Q1：`ImportError: No module named 'xxx'`

**原因**：依赖没装齐 / venv 没激活。

**解决**：
```bash
cd packages/server
uv venv  # 重建 venv
# 重新跑步骤 3 的安装命令
```

### Q2：CLI 报 `KeyError: 'internal-xhs'` 或 Provider 找不到

**原因**：`.env` 没配 / 路径不对。

**检查**：
```bash
# 1. 看 .env 是否存在
ls tradenest/.env

# 2. 当前目录跑 cli 时会从仓库根读 .env
cd tradenest                                   # 切到仓库根
uv run --directory packages/server python -m tradenest.cli info
```

### Q3：调 LLM 报 `403 / 401 / Unauthorized`

#### 如果是 internal-xhs（小红书内部网关）

**原因**：不在小红书内网 / VPN 没连 / 或 `x-adapter-user-email` 不是合法账号。

**解决**：
- 确认本机能 ping 通 `codewiz.devops.xiaohongshu.com`：
  ```bash
  curl -sS -o /dev/null -w "%{http_code}\n" http://codewiz.devops.xiaohongshu.com/
  # 应该返回 302 或 200
  ```
- 不在内网 → 改用其他 Provider（详见第 6 节）

#### 如果是 anthropic-public

**原因**：API key 不对 / 不能访问 api.anthropic.com（中国大陆需要代理）。

**解决**：填对 `TRADENEST_ANTHROPIC_API_KEY` + 配代理（见第 5 节）。

### Q4：调 AkShare 工具报 `Connection aborted`

**原因**：本机无法访问东方财富 / 雪球等数据源（防火墙 / 代理问题）。

**解决**：
- 能访问就直接通（一般家用网络 OK）
- 不能访问 → 临时用 mock 工具：
  ```bash
  uv run python -m tradenest.cli ask "用 mock_get_stock_demo 查 600519"
  ```
- 或者切换到 Tushare（需要 token）

### Q5：合规审查把回答拦截了

**症状**：返回 "（系统检测到本次回复包含合规风险内容，已被拦截。）"

**原因**：LLM 输出了 `建议买入 / 目标价 / 看多 / 看空` 等违规词。

**这是按设计行为**——TradeNest 不能给具体投资建议。

**解决**：换合规问法：
```bash
# ❌ 违规
"我该买入贵州茅台吗？"  → 触发拦截

# ✅ 合规
"贵州茅台的基本面数据是什么？"
"贵州茅台 PE 在历史什么分位？"
"贵州茅台最近的多空辩论焦点是什么？"
```

详见 [docs/0002-合规边界.md](./0002-合规边界.md)。

### Q6：`uv: command not found`

**原因**：uv 没装 / 没在 PATH。

**解决**：
```bash
# 重装
curl -LsSf https://astral.sh/uv/install.sh | sh

# 加到当前 shell（如果 install 脚本没自动加）
source $HOME/.cargo/env  # 或 ~/.local/bin/env，看 install 输出提示

# 验证
uv --version
```

### Q7：Python 版本不够

**症状**：报 `requires Python >=3.12` 类似错误。

**解决**：
- macOS: `brew install python@3.11`（3.11+ 都能跑，pyproject 写的 3.12 是建议值）
- 或者 uv 自动装：`uv venv --python 3.11`

如果你已经有 3.11，编辑 `packages/server/pyproject.toml`：

```toml
requires-python = ">=3.11"  # 从 3.12 改成 3.11
```

### Q8：CLI 中文乱码

**原因**：Windows 终端编码问题。

**解决**：
```cmd
chcp 65001
```

或者改用 Windows Terminal（推荐）。

### Q9：FastAPI 启动报端口被占用

**症状**：`[Errno 48] Address already in use`

**解决**：换端口或杀掉占用进程：

```bash
# Mac/Linux 查 8000 端口
lsof -i :8000
kill -9 <PID>

# 或换端口启动
uv run uvicorn tradenest.main:app --reload --port 8001
```

### Q10：`Resource not accessible by personal access token`（git push）

**原因**：GitHub Token 权限不足。

**解决**：用 Classic Token（勾 `repo` 一个就够）。详见 [GitHub Token 文档](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。

## 5. 配置说明

### .env 文件位置

```
tradenest/
├── .env              ← 配置在仓库根目录
├── .env.example      ← 模板
└── packages/
    └── server/
```

### 关键配置项

| 变量 | 默认 | 说明 |
|------|------|------|
| `TRADENEST_DEFAULT_PROVIDER_ID` | `internal-xhs` | 默认走哪个 LLM Provider |
| `TRADENEST_DEBUG` | `true` | 开发模式（详细日志） |
| `TRADENEST_LOG_LEVEL` | `INFO` | 日志级别（DEBUG/INFO/WARNING）|
| `TRADENEST_PORT` | `8000` | Web 服务端口 |
| `TRADENEST_AGENT_MAX_LOOP_TURNS` | `10` | Agent 最大循环轮数 |
| `TRADENEST_COMPLIANCE_STRICT` | `true` | 严格合规模式 |

### LLM Provider 配置

| 变量 | 用途 |
|------|------|
| `TRADENEST_ANTHROPIC_API_KEY` | 公网 Anthropic（留空则禁用此 Provider）|
| `TRADENEST_OPENAI_API_KEY` | OpenAI（留空则禁用） |
| `TRADENEST_DEEPSEEK_API_KEY` | DeepSeek（留空则禁用） |

### HTTP 代理（如需要）

```env
HTTPS_PROXY=http://your-proxy:port
HTTP_PROXY=http://your-proxy:port
NO_PROXY=localhost,127.0.0.1,xiaohongshu.com
```

## 6. 多 Provider 切换

TradeNest 支持多家 LLM。不同场景换不同的：

### 场景 1：在小红书内网（默认）

什么都不改，直接跑：

```bash
uv run python -m tradenest.cli ask "你好"
```

### 场景 2：用公网 Anthropic

改 `.env`：

```env
TRADENEST_DEFAULT_PROVIDER_ID=anthropic-public
TRADENEST_ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxx
```

如果在中国大陆需要代理：

```env
HTTPS_PROXY=http://your-proxy:port
```

### 场景 3：用 DeepSeek（性价比之选）

```env
TRADENEST_DEFAULT_PROVIDER_ID=deepseek
TRADENEST_DEEPSEEK_API_KEY=sk-xxxxxxxxxxx
```

### 场景 4：CLI 指定 Provider（不改 .env）

```bash
uv run python -m tradenest.cli ask "你好" --provider deepseek
uv run python -m tradenest.cli ask "你好" --provider anthropic-public
```

### 查看已注册的 Provider

```bash
uv run python -m tradenest.cli info
```

## 8. 还跑不通？

```bash

# 1. 系统信息
uv run python -m tradenest.cli info > /tmp/tn-info.txt 2>&1

# 2. 完整 debug 日志

  uv run python -m tradenest.cli ask "你好" > /tmp/tn-debug.txt 2>&1

# 3. 环境
uv --version > /tmp/tn-env.txt
python3 --version >> /tmp/tn-env.txt
uname -a >> /tmp/tn-env.txt
```

## 版本号规则（SemVer）

```
v MAJOR . MINOR . PATCH

例：v1.2.3
```

### MAJOR

- 破坏性变更
- 数据 schema 不向后兼容
- API 协议大改

### MINOR

- 新功能
- 向后兼容的 API 变化
- 数据 schema 向后兼容的扩展

### PATCH

- Bug 修复
- 文档更新
- 小幅性能改进

---

## 变更类型分类

每个版本的变更按以下类型分组：

- **Added** — 新功能
- **Changed** — 现有功能的变化
- **Deprecated** — 即将移除的功能（标记不删）
- **Removed** — 已删除的功能
- **Fixed** — Bug 修复
- **Security** — 安全相关修复
- **Compliance** — 合规规则更新

---

## 历史版本归档

发布后的版本应**冻结不再修改**。如需修订历史 changelog，应在新版本下用 "Notes" 类型说明。

---

## 维护责任

每个 PR 必须**同步更新 CHANGELOG**：
- 新功能 → Unreleased § Added
- Bug 修复 → Unreleased § Fixed
- 文档 → Unreleased § Changed

发版时：
1. 把 `[Unreleased]` 改为版本号 + 日期
2. 在顶部加新的 `[Unreleased]` 占位
3. 创建 git tag
4. 推到 GitHub Release

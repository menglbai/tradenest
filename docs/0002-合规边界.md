## 1. 监管背景

### 1.1 中国证券投资咨询业务管理

#### 核心法规

| 法规 | 发布时间 | 关键内容 |
|------|---------|---------|
| **《证券、期货投资咨询管理暂行办法》** | 1997（多次修订） | 未取得资格不得从事证券投资咨询 |
| **《证券投资顾问业务暂行规定》** | 2010 | 投资顾问业务的牌照要求与禁止行为 |
| **《关于规范金融领域 AI 应用的通知》** | 2024 | AI 工具不得提供具体投资建议 |
| **《个人信息保护法》** | 2021 | 用户数据处理规范 |
| **《数据安全法》** | 2021 | 数据出境与分类管理 |
| **《互联网信息服务算法推荐管理规定》** | 2022 | 算法推荐合规 |

#### 处罚现实

未持牌从事证券投资咨询的常见处罚：

- 责令停止违法行为
- 没收违法所得
- 罚款（违法所得 1-10 倍）
- 严重情况：**追究刑事责任（非法经营罪）**

近年案例：
- 大量"荐股 App"被下架
- 直播间荐股全面整顿
- 微信群推荐股票被立案
- 公众号"内幕消息"被处罚

#### 持牌的难度

- **个人**：基本不可能拿到证券投资咨询业务牌照
- **创业公司**：需注册资本 100 万以上 + 5 名持证投资顾问
- **TradeNest 选择**：**永远不申请该牌照**——通过严守红线规避

### 1.2 国际监管参考（仅作了解）

| 地区 | 监管机构 | 关键要求 |
|------|---------|---------|
| 美国 | SEC + FINRA | 投资顾问需注册 RIA |
| 欧盟 | ESMA / MiFID II | 投资建议受 MiFID II 严格管控 |
| 香港 | SFC | Type 4 牌照（建议证券） |
| 新加坡 | MAS | CMS 牌照 |

> TradeNest v1 阶段**仅服务中国大陆用户**，按中国法规执行。

## 2. 红线清单（绝对不做）

### 2.1 第一类：投资建议（Investment Advice）

#### ❌ 不推荐具体证券

**禁止输出**：
- "建议你买入 X / 卖出 X"
- "推荐你关注 Y"
- "X 是个好机会 / 值得买"
- "今日推荐 / 一周推荐 / 月度金股"
- "强烈推荐 / 强烈看好"
- "我建议你..."（关于具体证券的）

**允许输出**：
- "X 公司 2024 年 ROIC 是 18%"（事实）
- "X 公司过去 3 年收入复合增速 25%"（事实）
- "你 3 个月前对 X 的判断是 Y"（用户历史）
- "看多方观点是 A，看空方观点是 B"（多视角呈现）

#### ❌ 不预测股价

**禁止输出**：
- "X 会涨到 Y 元"
- "目标价 X"
- "短期内会涨 / 跌"
- "突破 X 元后会..."
- "支撑位 / 压力位"（带方向性预测的）

**允许输出**：
- "X 历史 PE 区间是 20-40，当前 35"（事实统计）
- "X 当前估值在过去 5 年 80% 分位"（事实统计）
- 历史走势图（不带预测线）

#### ❌ 不替下单

- 不连接券商交易 API
- 不接受用户的"代我下单"授权
- 不开发"自动执行交易"功能

#### ❌ 不承诺收益

**禁止输出**：
- "用 TradeNest 你能赚 X%"
- "我们的成功率 N%"
- "保证收益"
- "稳赚不赔"

### 2.2 第二类：误导性陈述

#### ❌ 不夸大 AI 能力

**禁止输出**：
- "AI 永远不会错"
- "AI 比人类更准"
- "AI 能预测市场"

#### ❌ 不引用未经证实的信息

**禁止行为**：
- 编造研报内容
- 引用不存在的数据
- 给出未经验证的"内幕"

### 2.3 第三类：合规与隐私

#### ❌ 不未经授权处理用户数据

- 不上传用户研究笔记到第三方
- 不分析用户数据用于训练模型
- 不与第三方共享用户身份信息

#### ❌ 不绕过付费墙

- 不破解第三方 App
- 不批量爬取付费内容
- 不分发盗版数据

## 3. 边界灰区（可做但需谨慎）

### 3.1 可做的事

#### ✅ 信息整理

**可以**：
- 把多个信息源聚合到一处
- 用结构化方式呈现（表格、列表）
- 提取关键事实

**注意**：
- 必须标明数据来源
- 不修改 / 不歪曲原始数据

#### ✅ 多视角分析

**可以**：
- 输出"看多方观点 + 看空方观点"
- 用结构化框架打分（用户的 L2 框架）
- 多 Agent 辩论过程

**注意**：
- **不能给最终结论**（"建议买入"）
- 必须呈现**辩论过程**而非单一结论
- 用户的判断必须是用户自己做出的

#### ✅ 跨时间反馈

**可以**：
- 显示用户历史决策
- 对比当前判断与历史判断
- 显示用户判断的实际结果

**注意**：
- 不下"对错"结论
- 让用户自己反思

#### ✅ 苏格拉底反问

**可以**：
- 问"你这个判断的关键假设是什么"
- 问"你 3 个月前说过 X，现在为什么变了"
- 问"如果你错了会怎样"

**注意**：
- 反问不能引导到"建议买入"
- 反问的目的是**让用户想清楚**，不是**让用户买**

#### ✅ 风险提示

**可以**：
- 明确告知投资风险
- 提示用户的仓位集中度
- 提示超出能力圈
- 提示决策频率异常

**注意**：
- 风险提示不构成投资建议
- 必须基于事实和用户的 L2 框架

### 3.2 灰区操作的边界示例

#### 示例 1：用户问"贵州茅台值得买吗"

**❌ 错误回答**：
> "贵州茅台基本面优秀，建议买入。"

**❌ 错误回答（隐性建议）**：
> "贵州茅台是一只优质标的，值得关注。"

**✅ 正确回答**：
> "贵州茅台 2025 年财报显示 ROIC 18%、毛利率 91%，都在你的 L2 框架优秀分位。
> 从你的研究历史看，3 个月前你判断'估值偏高'，当时 PE 30，现在 PE 28。
> 看多方核心论据是 [A, B, C]，看空方核心论据是 [X, Y, Z]。
> 几个反问：
> 1. 你 3 个月前的"估值偏高"判断现在变了什么？
> 2. 你的能力圈框架里，消费品是 strong 项 — 这个标的符合你的标准吗？
> 3. 如果你错了，最大可能的失败原因是什么？
> ⚠️ 以上仅为信息整理，不构成投资建议。"

#### 示例 2：用户问"AI 觉得茅台会涨吗"

**❌ 错误回答**：
> "短期内可能会涨。"

**✅ 正确回答**：
> "我不能预测股价——这违反我的设计原则。
> 我能告诉你的事实：
> - 当前 PE 28，处于过去 5 年的 60% 分位
> - 最近 3 个月北向资金净流入 X 亿
> - 最近一份机构研报评级是 [事实]
> 但这些数据**不构成股价方向预测**。"

#### 示例 3：用户问"目标价多少"

**❌ 错误回答**：
> "短期目标 ¥1800，中期目标 ¥2000。"

**✅ 正确回答**：
> "我不会给目标价——这超出我的合规边界。
> 你可以用你的 L2 框架自己估算：
> - 你框架里的 valuation 维度要求 PE < 30
> - 当前 PE 28
> - 历史均值 PE 25
> 这些是**事实**，估值结论由你做出。"

## 4. 输出审查机制

### 4.1 三道防线

```
┌──────────────────────────────────────────┐
│ 第一道：System Prompt 强约束              │
│ 在每个 Agent 的 system prompt 中写明红线  │
└─────────────┬────────────────────────────┘
              ↓
┌──────────────────────────────────────────┐
│ 第二道：输出后置审查（关键词过滤）         │
│ 每条输出经过正则审查再展示                 │
└─────────────┬────────────────────────────┘
              ↓
┌──────────────────────────────────────────┐
│ 第三道：用户协议确认                      │
│ 首次启动让用户明确"知道这不是投顾"          │
└──────────────────────────────────────────┘
```

### 4.2 第一道：System Prompt 模板

每个 Agent 必须包含的合规约束：

```
【合规约束 - 必须严格遵守】
你是 TradeNest 的研究助手 Agent，**不是投资顾问**。

绝对禁止：
- ❌ 推荐具体证券（"建议买入/卖出 X"）
- ❌ 预测股价（"X 会涨到 Y"、目标价、支撑压力位）
- ❌ 给买卖建议（"建议加仓/减仓"）
- ❌ 承诺收益（"用了能赚 N%"）
- ❌ 编造数据或研报

允许：
- ✅ 整理客观信息
- ✅ 多视角呈现（看多 vs 看空）
- ✅ 按用户的 L2 框架结构化分析
- ✅ 反问引导用户自己思考
- ✅ 提示风险

每次输出后必须包含：
"⚠️ 以上仅为研究参考，不构成投资建议。"

如果用户直接要求你"推荐股票"或"告诉我买啥"：
- 礼貌拒绝
- 解释你不是投顾
- 引导他自己做研究
```

### 4.3 第二道：输出后置审查

#### 关键词黑名单（中文）

```python
# 简化示例
FORBIDDEN_PATTERNS = [
    # 直接建议
    r"建议(买入|卖出|加仓|减仓|抄底|逃顶)",
    r"推荐(买入|你买|关注)",
    r"应该(买|卖|入手|清仓)",
    
    # 预测
    r"目标价[\s:：]*\d",
    r"会涨到\s*\d",
    r"突破.*会",
    r"短期内会(涨|跌)",
    
    # 承诺
    r"必涨|稳赚|保赚|包赢|稳赚不赔",
    r"成功率\s*\d+\s*%",
    r"收益率.*超过",
    
    # 误导
    r"AI 比人类(更准|更聪明)",
    r"内幕(消息|信息)",
]

WARNING_PATTERNS = [  # 触发警告但不拦截
    r"机会|时机",
    r"看好|看多|看空",
    r"低估|高估",
]
```

#### 审查代码

```python
import re
from typing import NamedTuple

class ComplianceCheck(NamedTuple):
    passed: bool
    violations: list[str]
    warnings: list[str]

def check_compliance(text: str) -> ComplianceCheck:
    violations = []
    warnings = []
    
    for pattern in FORBIDDEN_PATTERNS:
        matches = re.findall(pattern, text)
        if matches:
            violations.append(f"禁用模式 {pattern}: {matches}")
    
    for pattern in WARNING_PATTERNS:
        matches = re.findall(pattern, text)
        if matches:
            warnings.append(f"敏感模式 {pattern}: {matches}")
    
    return ComplianceCheck(
        passed=len(violations) == 0,
        violations=violations,
        warnings=warnings,
    )
```

#### 处理流程

```python
async def safe_agent_output(raw_output: str) -> str:
    check = check_compliance(raw_output)
    
    if not check.passed:
        # 违规 → 重新生成
        retry_output = await regenerate_with_correction(
            raw_output, 
            check.violations,
        )
        # 再次审查
        recheck = check_compliance(retry_output)
        if not recheck.passed:
            # 仍违规 → 返回安全模板
            return SAFE_FALLBACK_TEMPLATE
        return retry_output
    
    if check.warnings:
        # 警告 → 记录日志，添加免责声明
        log_warning(check.warnings)
        return raw_output + "\n\n⚠️ 以上仅为研究参考，不构成投资建议。"
    
    return raw_output
```

## 5. 类似产品合规对比

### 5.1 主流产品如何做

| 产品 | 类型 | 合规策略 |
|------|------|---------|
| **同花顺问财** | 大厂 AI 助手 | 严格规避具体推荐，定位"信息查询" |
| **雪球 AI** | 社区 AI | 拒绝"该买什么"类问题，转向社区讨论 |
| **华泰涨乐 AI** | 券商 AI | 持牌机构，但 AI 层仍不直接建议 |
| **TradingAgents-CN** | 开源框架 | "学习平台"定位，明确不实盘 |
| **同花顺 i 问财** | 数据查询 | 数据查询为主，避开建议 |
| **东方财富 AI** | 大厂 | 信息聚合 + 数据查询，不建议 |

### 5.2 我们的策略

**TradeNest 比上述产品更严格**：

| 维度 | 主流产品 | TradeNest |
|------|---------|----------|
| 是否给"机会提示" | 部分会 | ❌ 不给 |
| 是否给目标价 | 部分会 | ❌ 不给 |
| 是否暗示买入 | 部分会 | ❌ 不暗示 |
| 是否做多空辩论 | 不做 | ✅ 做（但呈现过程） |
| 是否记录用户决策 | 不做 | ✅ 做 |
| 是否反问用户 | 不做 | ✅ 做 |

**核心差异**：我们做"过程透明"和"反问"，**不做结论**。

## 6. 数据合规

### 6.1 个人信息保护

#### 用户数据本地优先

- L1-L5 五层记忆默认存储在**用户本地**
- 同步到云只在**用户明确开启**时
- 云同步使用**端到端加密**

#### 不收集的数据

- ❌ 用户身份证 / 银行卡 / 密码
- ❌ 用户的真实持仓金额（除非用户主动填）
- ❌ 用户的实际交易记录

#### 收集的数据（仅本地）

- ✅ 用户的研究笔记（自己写的）
- ✅ 用户的对话历史（与 AI 的对话）
- ✅ 用户的研究框架（自己定义的）

### 6.2 第三方数据源使用

#### 数据源合规清单

| 数据源 | 使用方式 | 合规状态 |
|-------|---------|---------|
| AkShare | API 调用 | ✅ 开源 MIT，可商用 |
| Tushare Pro | API + Token | ✅ 用户自己的 Token |
| 东方财富 API | HTTP 请求 | ⚠️ 非官方接口，仅个人研究用途 |
| 微信公众号 | Playwright 用户登录 | ⚠️ 仅本地展示，不公开传播 |
| 雪球 | Playwright 用户登录 | ⚠️ 同上 |
| 知乎 | Playwright 用户登录 | ⚠️ 同上 |

#### 数据使用原则

1. **仅供用户个人研究**
2. **不公开传播第三方付费内容**
3. **不批量爬取**（避免账号封禁 + 法律风险）
4. **遵守原网站 robots.txt 和 ToS**
5. **数据存本地，不上传共享**

### 6.3 LLM Provider 数据安全

| Provider | 数据政策 | 应对措施 |
|----------|---------|---------|
| Anthropic | 默认不用于训练（API） | ✅ 直接用 |
| OpenAI | 默认不用于训练（API） | ✅ 直接用 |
| DeepSeek | 国内云服务 | ⚠️ 不发送敏感个人信息 |
| Qwen | 国内云服务 | ⚠️ 同上 |

#### 敏感信息脱敏

调用 LLM 时**自动脱敏**：
- 用户姓名 → "用户"
- 持仓金额 → 仓位百分比
- 真实账户信息 → 不传

## 7. 应急预案

### 7.1 监管约谈

#### 触发场景

- 收到证监会 / 网信办 / 工信部约谈电话
- 收到正式函件

#### 处理步骤

1. **立即记录**：约谈时间 / 约谈机构 / 约谈人 / 约谈内容
2. **不签字**：未经法律审查不签任何文件
3. **联系律师**：24 小时内咨询专业证券律师
4. **配合调查**：提供合规审查日志
5. **停服评估**：判断是否需要暂时下线

### 7.2 用户投诉

#### 投诉类型与应对

| 投诉类型 | 应对 |
|---------|------|
| "AI 推荐让我亏钱了" | 提供输出审查日志，证明无具体建议 |
| "数据不准导致决策错误" | 数据来源标注 + 免责声明 |
| "侵犯隐私" | 提供数据本地化证明 |
| "AI 误导" | 调用合规审查日志 |

#### 防御性证据

每条 AI 输出**必须可追溯**：
- 输入是什么
- 哪些 Agent 处理了
- 哪些工具被调用
- 经过了哪些合规检查
- 最终输出是什么

数据保留 **3 年以上**。

### 7.3 律师函 / 起诉

1. 不直接回应（避免承认）
2. 转交律师
3. 调取所有相关日志

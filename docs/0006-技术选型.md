## 1. Python 3.12

### 候选

| 语言 | 金融生态 | LLM SDK | 性能 | 评估 |
|------|---------|---------|------|------|
| **Python 3.12** | ✅✅✅ | ✅✅✅ | 中 | ✅ 采用 |
| Node.js 20+ | ❌ | ✅✅✅ | 中高 | ❌ |
| Go 1.22 | ❌ | ⚠️ | 高 | ❌ |
| Rust 1.78 | ❌ | ⚠️ | 极高 | ❌ |

### 决策理由

1. **金融数据生态完整**：AkShare / Tushare / Pandas / NumPy / TA-Lib 都是 Python first
2. **LLM SDK 一线**：Anthropic / OpenAI / Google 的 Python SDK 通常是首发
3. **Agent 框架原生**：LangGraph / AutoGen / CrewAI 全是 Python
4. **数值精度成熟**：Decimal 模块、Pandas 的 financial 工具
5. **作者经验**：作者熟悉 Python 生态

### 为何 3.12 而非 3.13

- 3.13 较新，部分库可能有兼容问题
- 3.12 稳定 + 性能优化（PEP 709 / 692）
- async 性能在 3.12 显著提升

### 风险与缓解

| 风险 | 缓解 |
|------|------|
| Python 性能瓶颈 | asyncio + 关键路径用 Rust 写扩展 |
| GIL 限制并发 | 任务密集走 Celery + 多 worker |
| 类型系统不强制 | mypy strict 模式 |

## 2. FastAPI

### 候选

| 框架 | 异步 | 类型 | 文档 | 评估 |
|------|------|------|------|------|
| **FastAPI** | ✅ 原生 | ✅ Pydantic | ✅ 自动 OpenAPI | ✅ 采用 |

- FastAPI 在 v0.100+ 后变化较多 → 锁定 minor 版本

## 3. Anthropic Claude Agent SDK + LangGraph

### 候选对比（2026 年）

| 框架 | 控制粒度 | 学习曲线 | Claude Code 风味 | 多 Agent | 评估 |
|------|---------|---------|------------------|----------|------|
| **Anthropic Agent SDK** | 中 | 低 | ✅✅✅ | ⚠️ | 主用 |
| **LangGraph** | 高 | 高 | ❌ | ✅✅✅ | 复杂编排 |
| LangChain（agent） | 中 | 中 | ❌ | ⚠️ | 太重 |
| CrewAI | 低 | 极低 | ❌ | ✅ | 太黑盒 |
| AutoGen（Microsoft） | 中 | 中 | ❌ | ✅✅ | 风格冗长 |
| OpenAI Agents SDK | 中 | 低 | ❌ | ⚠️ | 偏 OpenAI 生态 |
| 自己写 | 极高 | - | - | - | 工作量爆炸 |

### 决策

**Anthropic SDK 做主 Agent loop + LangGraph 做复杂多 Agent 编排**

### 理由

1. **Anthropic SDK 跟 Claude Code 同源**：满足"用上 cc 技术"的核心目标
2. **LangGraph 状态机最强**：多空辩论、风控辩论需要复杂控制流
3. **互补**：SDK 简单清爽，LangGraph 编排强
4. **Day 1 简单**：先用 SDK 跑通，Phase 2 再引入 LangGraph

### 风险与缓解

| 风险 | 缓解 |
|------|------|
| 两套 API 学习成本 | 渐进引入（Day 1 只用 SDK） |
| 版本兼容 | pyproject.toml 锁版本 |
| Anthropic SDK 较新 | 关注 changelog |

## 4. PostgreSQL 16 + pgvector

### 候选

| 方案 | 关系 | 向量 | 一致性 | 运维 | 评估 |
|------|------|------|-------|------|------|
| **PG 16 + pgvector** | ✅ | ✅ | 强 | 简单 | ✅ 采用 |
| MongoDB（仿 TradingAgents-CN） | ⚠️ | ⚠️（atlas vector） | 弱 | 中 | ❌ |
| MySQL + Milvus | ✅ | ✅ | 中 | 复杂 | ❌ |
| Weaviate | ❌ | ✅ | - | 中 | ❌ |
| Qdrant | ❌ | ✅✅ | - | 简单 | ❌ |

### 决策理由

1. **关系强**：5 层记忆有复杂关联（笔记↔决策↔对话）
2. **向量原生**：pgvector 在 2026 年已经成熟（HNSW / IVFFlat 都支持）
3. **一栈搞定**：单一系统简化运维
4. **TimescaleDB 扩展**：未来时序数据可平滑扩展
5. **本地优先**：PG 本地跑容易

### 性能数据（截至 2026）

- pgvector HNSW 在 100 万向量级别 query < 10ms
- 个人项目数据量级足够

### 风险与缓解

| 风险 | 缓解 |
|------|------|
| 向量数据极大时性能下降 | 数据量到 1000 万再考虑迁专用向量库 |
| 单点 PG | 个人产品单点足够，云版再说 HA |

### 替代：SQLite + sqlite-vec（v1 简化部署）

为了让用户**零门槛**安装：
- 默认用 SQLite + sqlite-vec
- 进阶用户可切到 PG

## 5. Redis 7 + Celery

### Redis 候选

| 方案 | 速度 | 持久化 | 队列 | 评估 |
|------|------|-------|------|------|
| **Redis 7** | ✅✅✅ | ✅ | ✅ Streams | ✅ 采用 |
| Memcached | ✅✅✅ | ❌ | ❌ | 缺少持久化 |
| DragonflyDB | ✅✅✅✅ | ✅ | ✅ | 太新，社区小 |

Redis 用于：
- API 响应缓存（行情、新闻）
- Celery Broker
- WebSocket pub/sub

### Celery 候选

| 方案 | 成熟度 | 异步原生 | 学习曲线 | 评估 |
|------|-------|---------|---------|------|
| **Celery** | ✅✅✅ | ⚠️ | 中 | ✅ 采用 |
| Dramatiq | ✅ | ⚠️ | 低 | 候选 |
| RQ | ✅ | ❌ | 极低 | 简单场景 |
| Arq | ⚠️ | ✅ | 低 | 较新 |

### 决策

Celery，理由：
1. 最成熟的 Python 任务队列
2. 定时任务（Celery Beat）原生支持
3. 监控生态丰富（Flower）
4. 失败重试 / 链式任务等高级功能

风险：Celery 历史包袱大，配置复杂——通过预置配置模板缓解。

## 17. Claude Sonnet 4.6 / Opus 4.7（主 LLM）

### 候选（2026-05）

| 模型 | 强项 | 价格 | Context | 评估 |
|------|------|------|---------|------|
| **Claude Sonnet 4.6** | Agent 性能 | 中 | 1M | ✅ 默认 |
| **Claude Opus 4.7** | 复杂推理 | 高 | 1M | ✅ 关键场景 |
| GPT-5 | 综合 | 中高 | 长 | ✅ 备选 |
| Gemini 3.1 Pro | 多模态 | 中 | 长 | ⚠️ 备选 |
| **DeepSeek V3.2** | 性价比 | 极低 | 中 | ✅ 经济模式 |
| **Qwen3 Coder Plus** | 中文 | 低 | 中 | ✅ 国内备选 |

### 决策

- **默认**：Claude Sonnet 4.6（agent 性能最强）
- **重要分析**：Claude Opus 4.7（最深推理）
- **经济模式**：DeepSeek V3.2 / Qwen3
- **失败降级**：Anthropic → OpenAI → DeepSeek

### 路由策略

```python
def select_model(task_type: str, complexity: int) -> str:
    if task_type == "simple_query":
        return "deepseek-chat"  # 便宜
    if task_type == "analyst":
        return "claude-sonnet-4.6"  # 主力
    if task_type == "synthesis" and complexity > 7:
        return "claude-opus-4.7"  # 复杂综合
    return "claude-sonnet-4.6"
```

## 24. 总结：技术栈的"现代度"

我们的技术栈很多都是 2024-2026 年的"新主流"：

| 分类 | 老主流 → 新主流 |
|------|---------------|
| Python 包管理 | pip → poetry → **uv** |
| Python lint | flake8 + Black → **Ruff** |
| 前端 lint | ESLint + Prettier → **Biome** |
| 桌面 | Electron → **Tauri** |
| Agent 框架 | LangChain → **Anthropic SDK + LangGraph** |
| 浏览器扩展 | 原生 manifest → **WXT** |

这些选择都符合用户原话："**用最好的最合适的就行**"。
